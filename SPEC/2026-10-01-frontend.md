## 4. Páginas e fluxo

| Rota | Página | Conteúdo |
|---|---|---|
| `/login` | `LoginPage` | usuário + senha; erros `401` ("Credenciais inválidas") e `429` ("Muitas tentativas…") exibidos |

| `/marketing` | `MarketingPage` | lista de envios com `StatusBadge` + botão **Baixar planilha** (`/api/marketing/planilha`) |
| `/usuarios` | `UsuariosPage` **[admin]** | tabela (username, nome, perfil, ativo) · **Novo usuário** (`UsuarioForm`: username, nome, perfil, senha ≥ 8) · por linha: editar nome/perfil, ativar/desativar, redefinir senha; `409` exibidos. Operador que acessa a URL → redirect `/` |
| `*` | 404 | — |

`Layout`: nav (Processos, Agenda, Marketing, **Usuários** só pra admin), nome do usuário + perfil, **Minha senha** (`MinhaSenhaDialog` → `PUT /auth/senha`; `400` exibido), **Sair**. Toda rota exceto `/login` passa por `RotaProtegida` (`GET /auth/me` → loading / redirect `/login`); `/usuarios` passa também por `RotaAdmin`. Botões de ação admin são escondidos pra operador — o backend é quem nega (`403`).

Formatação: dinheiro (`string`) com `Intl.NumberFormat('pt-BR', { style: 'currency', currency: 'BRL' })`; datas ISO com `Intl.DateTimeFormat('pt-BR', ...)` no fuso local, sem deslocar o dia.

## 5. `api/client.ts`

- `api.get/post/put/del<T>(path, body?)`, base `/api`, `credentials: 'same-origin'`.
- Em `POST/PUT/PATCH/DELETE`, lê cookie `csrf_token` de `document.cookie` e manda header `X-CSRF-Token`. Sem cookie, manda a request mesmo assim (backend decide).
- Body `FormData` → não seta `Content-Type` (browser define o boundary).
- Resposta não-2xx → `throw new ApiError(status, detail)`; `detail` vem do JSON `ErroOut`, ou `"Erro inesperado"` quando o corpo não é JSON (ex.: 500 do nginx).
- `401` → chama callback `onNaoAutenticado` registrado pelo router (limpa `QueryClient`, redireciona `/login`).
- `403` com `detail: "Sem permissão"` → `ApiError` normal; o componente exibe a mensagem (não redireciona).
- `204` → resolve `undefined`.

## 6. Segurança no frontend

- `X-CSRF-Token` em toda mutação (acima).
- Markdown do edital com `react-markdown` **sem** `rehype-raw`; HTML cru vira texto. Nunca `dangerouslySetInnerHTML`.
- Nenhum segredo em `VITE_*` (tudo com prefixo `VITE_` vai pro bundle).
- Downloads (`/api/editais/:id/download`, `/api/marketing/planilha`) são links `<a href>` normais — o cookie de sessão vai junto.

## 7. Modo mock (MSW)

`VITE_API_MOCK=true` → `main.tsx` faz `await import('./api/mocks/browser')` e `worker.start({ onUnhandledRequest: 'bypass' })` antes de montar.

- `mocks/db.ts`: estado em memória tipado + `reset()`. Fixtures: usuários `admin`/`admin` (perfil `admin`) e `operador`/`operador` (perfil `operador`); 2 processos — um `recebido`, um `analisado` com checklist completo baseado em `SPEC/referencias/DOC 1 modelo checklist - imoveis.md` (processo 1003966-15.2022.4.01.4301, `tipo_justica: "federal"`, União Federal, dois bens com matrículas 6.351 e 6.235, valores fictícios plausíveis) e relatório com 4 etapas; 1 leilão agendado; 1 bloqueio.
- `mocks/handlers.ts`: **todas** as rotas da spec backend §3, mesmos status e `detail`, inclusive `/usuarios`, `PUT /auth/senha`, `GET /agenda/feriados`, `PUT /editais/:id`, `download?formato=docx` (blob vazio com o content-type certo). Login seta cookies `session` e `csrf_token` via `Set-Cookie`; 5 falhas → `429` + `Retry-After`. Autorização no mock é por `db.sessao` em memória (MSW em Node não grava `document.cookie`); header `X-CSRF-Token` não é validado. Rotas **[admin]** devolvem `403 Sem permissão` quando a sessão é de operador. `POST /processos/:id/analisar` espera 800 ms (0 ms em `MODE === 'test'`) e devolve a fixture; processo cujo `nome_arquivo` contém `semtexto` → `422`. `POST /editais` gera markdown simples (juiz, datas, matrículas, lances) a partir do checklist em memória.
- `mocks/regrasAgenda.ts`: `candidatos(hoje)`, `motivoIndisponivel(d, bloqueios, feriados)`, `sugerirDatas(hoje, bloqueios, feriados): Sugestao | null` implementam as regras reais da spec backend §3 (dia útil, feriado, bloqueio, D+7, janela 30–45 corridos; **sem** colisão entre leilões). Puras, tipadas e testadas. `mocks/feriados.ts`: lista fixa de feriados BR + PA de 2026 e 2027 (`{ data, motivo }[]`) usada pelo mock e por `GET /agenda/feriados`.
- Mesmos handlers em `browser.ts` (`setupWorker`) e `server.ts` (`setupServer`, Vitest).
- Nova rota no backend → novo handler no mesmo PR. Mock desatualizado = bug.

## 8. Testes (obrigatórios)

- Toda página/feature tem `*.test.tsx`: `renderComApp(ui, { rota })` (QueryClient `retry: false` + `MemoryRouter`), interação com `userEvent`, asserção no DOM.
- Rede sempre via MSW `server` (setup global em `test/setup.ts`: `listen` / `resetHandlers` + `db.reset()` / `close`). Cenário de erro: `server.use(...)` sobrescreve o handler no teste.
- Sem snapshot. Sem testar implementação. Nome descreve comportamento: `it('mostra erro de credenciais inválidas')`.
- Toda ação **[admin]** tem dois testes: visível e funcional logado como `admin`; ausente logado como `operador`.
- Casos mínimos por feature estão listados no plano `prompts/planos/2026-10-01-frontend.md`.
- Rodar: `cd src && docker compose exec frontend pnpm test -- src/features/<area>`.
