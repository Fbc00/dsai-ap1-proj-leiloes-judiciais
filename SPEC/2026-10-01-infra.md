## 4. Cloudflare Workers + Containers (produção)

Um Worker serve o frontend (Workers Static Assets) e encaminha `/api/*` pra um Container com a imagem `src/backend/Dockerfile` (estágio final `prod`). Exige plano Workers Paid.

```
src/worker/
├── package.json        pnpm; dev deps wrangler, typescript, vitest
│                       scripts: dev, deploy:prod (wrangler deploy), deploy:preview (wrangler preview), check (dry-run), typecheck (wrangler types + tsc), test
├── build-frontend.sh   copia ../frontend (sem node_modules/dist) pra .wrangler/frontend, pnpm install + build lá
├── wrangler.jsonc      build.command = build-frontend.sh (roda antes de dev, deploy, preview e types)
│                       · assets .wrangler/frontend/dist (SPA, run_worker_first: true) · container Backend (durable_object, ../backend/Dockerfile)
│                       · durable object BACKEND · ratelimit LOGIN_LIMITER 5/60s · vars · secrets.required
├── src/proxy.ts        roteamento: /api/* → container, resto → assets; headers de segurança em toda resposta;
│                       X-Forwarded-For = CF-Connecting-IP; X-Forwarded-Proto https; X-Request-ID; 429 no POST /api/auth/login acima do limite
├── src/index.ts        Durable Object Backend: sobe o container (standard-1, internet liberada, env vindo do Worker),
│                       espera a porta 8000 responder em /api/health, encaminha a requisição; dorme após 2h sem uso
└── test/proxy.test.ts  vitest (node) cobrindo proxy.ts
```

- **Mesma origem.** Frontend e API no mesmo domínio: o frontend chama `/api` relativo com `credentials: 'same-origin'`, os cookies `session` (HttpOnly) e `csrf_token` são `SameSite=strict` e o header `X-CSRF-Token` é lido do cookie. Sem CORS.
- **Headers.** `X-Content-Type-Options nosniff`, `X-Frame-Options DENY`, `Referrer-Policy strict-origin-when-cross-origin` e CSP estrita `default-src 'self'; img-src 'self' data:; style-src 'self' 'unsafe-inline'; connect-src 'self'`, aplicados pelo Worker em assets e API.
- **Uma instância** (`getByName("principal")`): o `MEDIA_ROOT` é local ao container.
- **Mídia efêmera.** Disco do container não persiste: PDFs e e-mails em `MEDIA_ROOT` se perdem quando o container dorme ou muda de versão. Persistência em R2 é pendência.
- **Banco** = Supabase (§2), URLs com `?ssl=require`. Migrations rodam nos workflows de deploy antes do `wrangler deploy`/`wrangler preview`. Backup: §2 (`pg_dump` manual no plano Free).
- **Vars** (`wrangler.jsonc`): `APP_ENV=prod`, `LOG_LEVEL=INFO`, `COOKIE_SECURE=true`, `LLM_PROVIDER=anthropic`, `EMAIL_BACKEND=smtp`, `SMTP_PORT=587`, `SMTP_TLS=true`.
- **Secrets** (`cd src/worker && pnpm exec wrangler secret put <NOME>`, valor digitado no prompt): `DATABASE_URL` (role `leiloes_app`), `ANTHROPIC_API_KEY`, `SMTP_HOST`, `SMTP_USER`, `SMTP_PASSWORD`, `EMAIL_FROM`, `MARKETING_EMAILS`. O container recebe `DATABASE_URL_MIGRATOR` igual a `DATABASE_URL` só pra validar o `Settings`; DDL roda no CI com a role `leiloes_owner`.
- **Primeiro usuário:** `criar-usuario` rodado localmente com `src/.env` apontando pro Supabase (README).
- **Previews** (`wrangler preview`, disparo manual, §7): bloco `previews` no `wrangler.jsonc` repete `durable_objects` (BACKEND) e `ratelimits` (namespace `1002`) e define vars próprias com `LLM_PROVIDER=fake` e `EMAIL_BACKEND=file`. Container e Durable Object são novos por Preview (o container vem do `containers` do topo). Secrets da Preview: `pnpm exec wrangler preview base-config secret put DATABASE_URL`, apontando pra um banco de staging, nunca o de produção.

Rodar local (Docker ligado; o `build.command` builda o frontend): `src/worker/.dev.vars` com os secrets e `DATABASE_URL` alcançável de dentro do container (host fora de `localhost` exige `?ssl=require`), `cd src/worker && pnpm dev` → `http://localhost:8787`. E2E contra o Worker: `cd src/e2e && E2E_BASE_URL=http://localhost:8787 pnpm test`.

## 5. Dockerfiles

**Backend** (`src/backend/Dockerfile`): base `ghcr.io/astral-sh/uv:python3.12-bookworm-slim`; usuário não-root `app`; `UV_COMPILE_BYTECODE=1`, `UV_LINK_MODE=copy`. Target `dev`: `uv sync --frozen` (com dev deps), `CMD` definido pelo compose. Target `prod`: `uv sync --frozen --no-dev`, `COPY app alembic alembic.ini`, `CMD ["uv","run","uvicorn","app.main:app","--host","0.0.0.0","--port","8000","--workers","2"]`.

## 6. nginx

**`src/nginx/dev.conf`**:
- `limit_req_zone $binary_remote_addr zone=login:10m rate=5r/m;`
- `server { listen 80; client_max_body_size 50m; }`
- `location /api/ { proxy_pass http://backend:8000; proxy_read_timeout 300s; proxy_set_header Host $host; X-Real-IP $remote_addr; X-Forwarded-For $remote_addr; X-Forwarded-Proto $scheme; X-Request-ID $request_id; }`
- `location = /api/auth/login { limit_req zone=login burst=3 nodelay; limit_req_status 429; proxy_pass http://backend:8000; (mesmos headers) }`
- `location / { proxy_pass http://frontend:5173; proxy_http_version 1.1; Upgrade/Connection "upgrade" (HMR websocket); }`
- Headers de segurança em todas as respostas (`add_header ... always`): `X-Content-Type-Options nosniff`, `X-Frame-Options DENY`, `Referrer-Policy strict-origin-when-cross-origin`. CSP **dev** (Vite/React Refresh precisam de inline script e websocket): `Content-Security-Policy "default-src 'self'; script-src 'self' 'unsafe-inline'; img-src 'self' data:; style-src 'self' 'unsafe-inline'; connect-src 'self' ws: wss:"`.

Em produção na Cloudflare os headers de segurança, a CSP estrita e o rate limit do login ficam no Worker (§4).

## 7. CI/CD (GitHub Actions)

Premissa: deploy na **Cloudflare** (Worker + Container, §4) via `wrangler deploy`. CI roda uv/pnpm direto no runner (única exceção ao "sempre Docker").

### `.github/workflows/ci.yml`
`on: pull_request` + `workflow_call`. `concurrency: { group: ci-${{ github.ref }}, cancel-in-progress: true }`. `permissions: contents: read`.

| Job | Passos |
|---|---|
| `backend` | `working-directory: src/backend`; service `postgres:16-alpine` (`POSTGRES_USER=leiloes_owner`, `POSTGRES_PASSWORD=ci`, `POSTGRES_DB=leiloes_test`, healthcheck `pg_isready`); `astral-sh/setup-uv@v6` com `enable-cache: true`; `uv python install 3.12`; `uv sync --frozen`; `uv run ruff check .`; `uv run ruff format --check .`; `uv run pytest` com env: `DATABASE_URL_TEST=postgresql+asyncpg://leiloes_owner:ci@localhost:5432/leiloes_test` (e `DATABASE_URL`, `DATABASE_URL_MIGRATOR` iguais), `APP_ENV=test`, `LLM_PROVIDER=fake`, `EMAIL_BACKEND=file`, `MEDIA_ROOT=${{ runner.temp }}/media`, `POSTGRES_PASSWORD=ci`, `DB_APP_PASSWORD=ci` e demais obrigatórias do `Settings` |
| `frontend` | `working-directory: src/frontend`; `pnpm/action-setup@v4`; `actions/setup-node@v5` (node 22, `cache: pnpm`, `cache-dependency-path: src/frontend/pnpm-lock.yaml`); `pnpm install --frozen-lockfile`; `pnpm typecheck`; `pnpm lint`; `pnpm test`; `pnpm build` |
| `worker` | em `src/worker`: `pnpm install --frozen-lockfile`, `pnpm typecheck`, `pnpm test`, `pnpm check` (`wrangler deploy --dry-run`, sem credencial; o `build.command` builda o frontend e o dry-run builda a imagem do container a partir de `src/backend/Dockerfile`) |
| `seguranca` | `uv run --with pip-audit pip-audit` em `src/backend`; `pnpm audit --audit-level=high` em `src/frontend` |
| `e2e` | `continue-on-error: true` (até estabilizar); `cp src/.env.example src/.env`; `docker compose -f src/docker-compose.yml up -d --build --wait`; `docker compose ... exec -T backend uv run alembic upgrade head`; `echo "admin12345" \| docker compose ... exec -T backend uv run python -m app.cli criar-usuario admin --nome Admin --perfil admin --senha-stdin`; em `src/e2e`: `pnpm install --frozen-lockfile`, `pnpm exec playwright install --with-deps chromium`, `pnpm test`; `actions/upload-artifact` do `playwright-report/` em falha; `docker compose ... down -v` no `always` |

### `.github/workflows/deploy-preview.yml`
`on: workflow_dispatch` — só disparo manual pelo GitHub Actions, na branch escolhida. Inputs: `acao` (`deploy` | `remover`) e `nome` (opcional; vazio = nome da branch). Nome normalizado: minúsculas, `[^a-z0-9]` → `-`, até 24 caracteres. URL `<nome>-dsai-ap1-proj-leiloes-judiciais.<subdomínio>.workers.dev`. `concurrency` por branch com cancelamento.

| Job | Passos |
|---|---|
| `deploy` | `acao == deploy`; `environment: preview`; migrations no banco de staging (`DATABASE_URL`/`DATABASE_URL_MIGRATOR` do environment `preview`); `pnpm install --frozen-lockfile` e `pnpm run deploy:preview --name <nome>` em `src/worker` |
| `remover` | `acao == remover`; `environment: preview`; `wrangler preview delete --name <nome> --skip-confirmation` |

### `.github/workflows/deploy-prod.yml`
`on: workflow_dispatch` — só disparo manual pelo GitHub Actions, a partir de `main`. Único caminho de deploy de produção.

| Job | Passos |
|---|---|
| `ci` | `if: github.ref == 'refs/heads/main'`; `uses: ./.github/workflows/ci.yml` |
| `deploy` | `needs: ci`; `environment: production` (required reviewer = aprovação manual); `concurrency` sem cancelamento; `uv sync --frozen --no-dev` + `uv run alembic upgrade head` em `src/backend` com `DATABASE_URL`/`DATABASE_URL_MIGRATOR` do environment `production` e `APP_ENV=prod`; `pnpm install --frozen-lockfile` e `pnpm run deploy:prod` em `src/worker` com `CLOUDFLARE_API_TOKEN`/`CLOUDFLARE_ACCOUNT_ID`; smoke `curl -fsS $APP_URL/api/health` com até 30 tentativas (partida a frio do container) |

### `.github/dependabot.yml`
`schedule.interval: weekly`; ecosystems `uv` (`/src/backend`), `npm` (`/src/frontend`, `/src/e2e`, `/src/worker`), `github-actions` (`/`), `docker` (`/src/backend` e `/src/frontend`).

### Configuração manual no GitHub
Secrets do repositório: `CLOUDFLARE_API_TOKEN` (permissão Workers Scripts + Containers + Durable Objects edit), `CLOUDFLARE_ACCOUNT_ID`. Environment `production` (required reviewer): secrets `DATABASE_URL` e `DATABASE_URL_MIGRATOR` (Supabase de produção, `?ssl=require`), variable `APP_URL` (ex.: `https://dsai-ap1-proj-leiloes-judiciais.<conta>.workers.dev`). Environment `preview`: secrets `DATABASE_URL` e `DATABASE_URL_MIGRATOR` do banco de staging. Workers Builds (integração Git da Cloudflare) desconectado: todo deploy sai do GitHub Actions. Branch protection em `main`: job `ci` verde + 1 review. Ativar secret scanning + push protection.

Rollback: `cd src/worker && pnpm exec wrangler rollback` (volta a versão do Worker). Migrations do banco não voltam.

Validação local dos workflows: `rtk docker run --rm -v "$PWD:/repo" -w /repo rhysd/actionlint:latest`.

## 8. E2E (`src/e2e/`, etapa BACKEND)

Playwright, **um** cenário feliz contra o compose dev com `LLM_PROVIDER=fake` e `EMAIL_BACKEND=file`, Chromium só.

```
src/e2e/
├── package.json          pnpm; dev dep @playwright/test; scripts: test = playwright test
├── playwright.config.ts  baseURL http://localhost (env E2E_BASE_URL), retries 1, trace on-first-retry, reporter html
├── fixtures/processo.pdf PDF com camada de texto (~2 KB), gerado uma vez com tests/fixtures.py do backend e commitado
└── tests/fluxo-completo.spec.ts
```

Cenário: login `admin`/`admin12345` → upload de `fixtures/processo.pdf` → abre o processo → **Analisar** → checklist exibe `1003966-15.2022.4.01.4301` e matrícula `6.351` → **Agendar** com a sugestão → card mostra as duas datas → **Gerar edital** → markdown contém o nome do juiz → **Enviar pra marketing** → status `enviado` → `/marketing` lista o envio. Asserções por texto visível; seletores por `getByRole`/`getByLabel`.

Rodar local: `cd src && docker compose up -d --build --wait && cd e2e && pnpm install && pnpm exec playwright install chromium && pnpm test` (usuário `admin` criado antes via CLI).

## 9. Logs

nginx (dev) e Worker (prod) propagam `X-Request-ID`; backend loga JSON em stdout (spec backend §6). Dev: `docker compose logs -f backend | jq` filtra por `request_id`. Prod: logs do Worker e do container no Workers Observability (`observability.enabled`).
