## 4. `src/docker-compose.prod.yml`

Alternativa self-hosted (um servidor com Docker Compose), fora do pipeline de deploy. Produção é o §10.

| Serviço | Definição |
|---|---|
| `postgres` | igual ao dev, **sem** porta exposta |
| `migrate` | `image: ghcr.io/${GHCR_OWNER}/leiloes-backend:${IMAGE_TAG:-latest}`, `build: {context: ./backend, target: prod}`, `command: uv run alembic upgrade head`, env `DATABASE_URL=${DATABASE_URL_MIGRATOR}`, `depends_on postgres: service_healthy`, `restart: "no"` |
| `backend` | mesma imagem/build, `uv run uvicorn app.main:app --host 0.0.0.0 --port 8000 --workers 2`, `env_file: .env`, volume `media:/data/media`, `depends_on migrate: condition: service_completed_successfully`, `restart: unless-stopped` |
| `nginx` | `image: ghcr.io/${GHCR_OWNER}/leiloes-nginx:${IMAGE_TAG:-latest}`, `build: {context: ., dockerfile: frontend/Dockerfile}`, porta `80:80`, `depends_on backend`, `restart: unless-stopped` |
| `backup` | `postgres:16-alpine`, `entrypoint: ["/bin/sh", "/backup.sh"]`, `./docker/backup/backup.sh:/backup.sh:ro`, volumes `backups:/backups` e `media:/data/media:ro`, env `PGHOST=postgres`, `PGUSER=${POSTGRES_USER}`, `PGPASSWORD=${POSTGRES_PASSWORD}`, `PGDATABASE=${POSTGRES_DB}`, `BACKUP_RETENCAO_DIAS=${BACKUP_RETENCAO_DIAS:-7}`, `depends_on postgres: service_healthy`, `restart: unless-stopped` |

`image:` **e** `build:` nos dois: local faz `build`, servidor faz `pull`. `GHCR_OWNER` e `IMAGE_TAG` vêm do `.env`. Volumes nomeados: `pgdata`, `media`, `backups`.

**`src/docker/backup/backup.sh`**: loop infinito — `pg_dump -Fc > /backups/pg-$(date +%F-%H%M).dump`; `tar czf /backups/media-$(date +%F-%H%M).tgz -C /data media`; `find /backups -type f -mtime +$BACKUP_RETENCAO_DIAS -delete`; `sleep 86400`. Loga uma linha por execução.
**Restore** (documentado no README): `docker compose -f docker-compose.prod.yml exec -T postgres pg_restore -U $POSTGRES_USER -d $POSTGRES_DB --clean --if-exists < pg-<data>.dump` e `docker compose -f docker-compose.prod.yml run --rm --no-deps --entrypoint tar -v $PWD/media-<data>.tgz:/b.tgz:ro backend xzf /b.tgz -C /data` (o `backend` monta `media` com escrita; o `backup` monta só leitura).

## 6. nginx

**`src/nginx/dev.conf`**:
- `limit_req_zone $binary_remote_addr zone=login:10m rate=5r/m;`
- `server { listen 80; client_max_body_size 50m; }`
- `location /api/ { proxy_pass http://backend:8000; proxy_read_timeout 300s; proxy_set_header Host $host; X-Real-IP $remote_addr; X-Forwarded-For $remote_addr; X-Forwarded-Proto $scheme; X-Request-ID $request_id; }`
- `location = /api/auth/login { limit_req zone=login burst=3 nodelay; limit_req_status 429; proxy_pass http://backend:8000; (mesmos headers) }`
- `location / { proxy_pass http://frontend:5173; proxy_http_version 1.1; Upgrade/Connection "upgrade" (HMR websocket); }`
- Headers de segurança em todas as respostas (`add_header ... always`): `X-Content-Type-Options nosniff`, `X-Frame-Options DENY`, `Referrer-Policy strict-origin-when-cross-origin`. CSP **dev** (Vite/React Refresh precisam de inline script e websocket): `Content-Security-Policy "default-src 'self'; script-src 'self' 'unsafe-inline'; img-src 'self' data:; style-src 'self' 'unsafe-inline'; connect-src 'self' ws: wss:"`.

Em produção na Cloudflare os headers de segurança, a CSP estrita e o rate limit do login ficam no Worker (§10).

**`src/nginx/prod.conf`**: igual, mas `location / { root /usr/share/nginx/html; try_files $uri /index.html; }`, cache longo pra `/assets/`, e CSP **estrita**: `"default-src 'self'; img-src 'self' data:; style-src 'self' 'unsafe-inline'; connect-src 'self'"`.

## 10. Cloudflare Workers + Containers (produção)

Um Worker serve o frontend (Workers Static Assets) e encaminha `/api/*` pra um Container com a imagem `src/backend/Dockerfile` (estágio final `prod`). Exige plano Workers Paid.

```
src/worker/
├── package.json        pnpm; dev deps wrangler, typescript, vitest
│                       scripts: build:frontend, dev, deploy (build:frontend + wrangler deploy), check (build:frontend + dry-run), typecheck (wrangler types + tsc), test
├── wrangler.jsonc      assets ../frontend/dist (SPA, run_worker_first: true) · container Backend (durable_object, ../backend/Dockerfile)
│                       · durable object BACKEND · ratelimit LOGIN_LIMITER 5/60s · vars · secrets.required
├── src/proxy.ts        roteamento: /api/* → container, resto → assets; headers de segurança em toda resposta;
│                       X-Forwarded-For = CF-Connecting-IP; X-Forwarded-Proto https; X-Request-ID; 429 no POST /api/auth/login acima do limite
├── src/index.ts        Durable Object Backend: sobe o container (standard-1, internet liberada, env vindo do Worker),
│                       espera a porta 8000 responder em /api/health, encaminha a requisição; dorme após 2h sem uso
└── test/proxy.test.ts  vitest (node) cobrindo proxy.ts
```

- **Mesma origem.** Frontend e API no mesmo domínio: o frontend chama `/api` relativo com `credentials: 'same-origin'`, os cookies `session` (HttpOnly) e `csrf_token` são `SameSite=strict` e o header `X-CSRF-Token` é lido do cookie. Sem CORS.
- **Headers.** `X-Content-Type-Options nosniff`, `X-Frame-Options DENY`, `Referrer-Policy strict-origin-when-cross-origin` e a CSP estrita do §6, aplicados pelo Worker em assets e API.
- **Uma instância** (`getByName("principal")`): o `MEDIA_ROOT` é local ao container.
- **Mídia efêmera.** Disco do container não persiste: PDFs e e-mails em `MEDIA_ROOT` se perdem quando o container dorme ou muda de versão. Persistência em R2 é pendência.
- **Banco** = Supabase (§2), URLs com `?ssl=require`. Migrations rodam no job `deploy` antes do `wrangler deploy`. Backup: §2.
- **Vars** (`wrangler.jsonc`): `APP_ENV=prod`, `LOG_LEVEL=INFO`, `COOKIE_SECURE=true`, `LLM_PROVIDER=anthropic`, `EMAIL_BACKEND=smtp`, `SMTP_PORT=587`, `SMTP_TLS=true`.
- **Secrets** (`cd src/worker && pnpm exec wrangler secret put <NOME>`, valor digitado no prompt): `DATABASE_URL` (role `leiloes_app`), `ANTHROPIC_API_KEY`, `SMTP_HOST`, `SMTP_USER`, `SMTP_PASSWORD`, `EMAIL_FROM`, `MARKETING_EMAILS`. O container recebe `DATABASE_URL_MIGRATOR` igual a `DATABASE_URL` só pra validar o `Settings`; DDL roda no CI com a role `leiloes_owner`.
- **Primeiro usuário:** `criar-usuario` rodado localmente com `src/.env` apontando pro Supabase (README).

Rodar local (Docker ligado): build do frontend em `src/frontend/dist`, `src/worker/.dev.vars` com os secrets e `DATABASE_URL` alcançável de dentro do container (host fora de `localhost` exige `?ssl=require`), `cd src/worker && pnpm dev` → `http://localhost:8787`. E2E contra o Worker: `cd src/e2e && E2E_BASE_URL=http://localhost:8787 pnpm test`.
