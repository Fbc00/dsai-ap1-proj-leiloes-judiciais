## 4. `src/docker-compose.prod.yml`

| Serviço | Definição |
|---|---|
| `postgres` | igual ao dev, **sem** porta exposta |
| `migrate` | `image: ghcr.io/${GHCR_OWNER}/leiloes-backend:${IMAGE_TAG:-latest}`, `build: {context: ./backend, target: prod}`, `command: uv run alembic upgrade head`, env `DATABASE_URL=${DATABASE_URL_MIGRATOR}`, `depends_on postgres: service_healthy`, `restart: "no"` |
| `backend` | mesma imagem/build, `uv run uvicorn app.main:app --host 0.0.0.0 --port 8000 --workers 2`, `env_file: .env`, volume `media:/data/media`, `depends_on migrate: condition: service_completed_successfully`, `restart: unless-stopped` |
| `nginx` | `image: ghcr.io/${GHCR_OWNER}/leiloes-nginx:${IMAGE_TAG:-latest}`, `build: {context: ., dockerfile: frontend/Dockerfile}`, porta `80:80`, `depends_on backend`, `restart: unless-stopped` |
| `backup` | `postgres:16-alpine`, `entrypoint: ["/bin/sh", "/backup.sh"]`, `./docker/backup/backup.sh:/backup.sh:ro`, volumes `backups:/backups` e `media:/data/media:ro`, env `PGHOST=postgres`, `PGUSER=${POSTGRES_USER}`, `PGPASSWORD=${POSTGRES_PASSWORD}`, `PGDATABASE=${POSTGRES_DB}`, `BACKUP_RETENCAO_DIAS=${BACKUP_RETENCAO_DIAS:-7}`, `depends_on postgres: service_healthy`, `restart: unless-stopped` |

`image:` **e** `build:` nos dois: local faz `build`, servidor faz `pull`. `GHCR_OWNER` e `IMAGE_TAG` vêm do `.env`. Volumes nomeados: `pgdata`, `media`, `backups`.

**`src/docker/backup/backup.sh`**: loop infinito — `pg_dump -Fc > /backups/pg-$(date +%F-%H%M).dump`; `tar czf /backups/media-$(date +%F-%H%M).tgz -C /data media`; `find /backups -type f -mtime +$BACKUP_RETENCAO_DIAS -delete`; `sleep 86400`. Loga uma linha por execução.
**Restore** (documentado no README): `docker compose -f docker-compose.prod.yml exec -T postgres pg_restore -U $POSTGRES_USER -d $POSTGRES_DB --clean --if-exists < pg-<data>.dump` e `docker compose -f docker-compose.prod.yml run --rm --no-deps --entrypoint tar -v $PWD/media-<data>.tgz:/b.tgz:ro backend xzf /b.tgz -C /data` (o `backend` monta `media` com escrita; o `backup` monta só leitura).

## 5. Dockerfiles

**Backend** (`src/backend/Dockerfile`): base `ghcr.io/astral-sh/uv:python3.12-bookworm-slim`; usuário não-root `app`; `UV_COMPILE_BYTECODE=1`, `UV_LINK_MODE=copy`. **Frontend/nginx** (`src/frontend/Dockerfile`, contexto `src/`): ver spec frontend §10.

## 6. nginx

**`src/nginx/dev.conf`**:
- `limit_req_zone $binary_remote_addr zone=login:10m rate=5r/m;`
- `server { listen 80; client_max_body_size 50m; }`
- `location /api/ { proxy_pass http://backend:8000; proxy_read_timeout 300s; proxy_set_header Host $host; X-Real-IP $remote_addr; X-Forwarded-For $remote_addr; X-Forwarded-Proto $scheme; X-Request-ID $request_id; }`
- `location = /api/auth/login { limit_req zone=login burst=3 nodelay; limit_req_status 429; proxy_pass http://backend:8000; (mesmos headers) }`
- `location / { proxy_pass http://frontend:5173; proxy_http_version 1.1; Upgrade/Connection "upgrade" (HMR websocket); }`
- Headers de segurança em todas as respostas (`add_header ... always`): `X-Content-Type-Options nosniff`, `X-Frame-Options DENY`, `Referrer-Policy strict-origin-when-cross-origin`. CSP **dev** (Vite/React Refresh precisam de inline script e websocket): `Content-Security-Policy "default-src 'self'; script-src 'self' 'unsafe-inline'; img-src 'self' data:; style-src 'self' 'unsafe-inline'; connect-src 'self' ws: wss:"`.

**`src/nginx/prod.conf`**: igual, mas `location / { root /usr/share/nginx/html; try_files $uri /index.html; }`, cache longo pra `/assets/`, e CSP **estrita**: `"default-src 'self'; img-src 'self' data:; style-src 'self' 'unsafe-inline'; connect-src 'self'"`.

## 7. CI/CD (GitHub Actions)

Premissa: deploy em **um servidor** com Docker Compose, acessado por SSH. Registry = GHCR do próprio repositório. CI roda uv/pnpm direto no runner (única exceção ao "sempre Docker").

### `.github/workflows/ci.yml`
`on: pull_request` + `workflow_call`. `concurrency: { group: ci-${{ github.ref }}, cancel-in-progress: true }`. `permissions: contents: read`.

| Job | Passos |
|---|---|
| `backend` | `working-directory: src/backend`; service `postgres:16-alpine` (`POSTGRES_USER=leiloes_owner`, `POSTGRES_PASSWORD=ci`, `POSTGRES_DB=leiloes_test`, healthcheck `pg_isready`); `astral-sh/setup-uv@v6` com `enable-cache: true`; `uv python install 3.12`; `uv sync --frozen`; `uv run ruff check .`; `uv run ruff format --check .`; `uv run pytest` com env: `DATABASE_URL_TEST=postgresql+asyncpg://leiloes_owner:ci@localhost:5432/leiloes_test` (e `DATABASE_URL`, `DATABASE_URL_MIGRATOR` iguais), `APP_ENV=test`, `LLM_PROVIDER=fake`, `EMAIL_BACKEND=file`, `MEDIA_ROOT=${{ runner.temp }}/media`, `POSTGRES_PASSWORD=ci`, `DB_APP_PASSWORD=ci` e demais obrigatórias do `Settings` |
| `frontend` | `working-directory: src/frontend`; `pnpm/action-setup@v4`; `actions/setup-node@v5` (node 22, `cache: pnpm`, `cache-dependency-path: src/frontend/pnpm-lock.yaml`); `pnpm install --frozen-lockfile`; `pnpm typecheck`; `pnpm lint`; `pnpm test`; `pnpm build` |
| `docker` | `docker/setup-buildx-action@v3`; `docker/build-push-action@v6` `push: false` pra `leiloes-backend` (`context: src/backend`, `target: prod`) e `leiloes-nginx` (`context: src`, `file: src/frontend/Dockerfile`), `cache-from/cache-to: type=gha` |
| `seguranca` | `uv run --with pip-audit pip-audit` em `src/backend`; `pnpm audit --audit-level=high` em `src/frontend` |
| `e2e` | `continue-on-error: true` (até estabilizar); `cp src/.env.example src/.env`; `docker compose -f src/docker-compose.yml up -d --build --wait`; `docker compose ... exec -T backend uv run alembic upgrade head`; `echo "admin12345" \| docker compose ... exec -T backend uv run python -m app.cli criar-usuario admin --nome Admin --perfil admin --senha-stdin`; em `src/e2e`: `pnpm install --frozen-lockfile`, `pnpm exec playwright install --with-deps chromium`, `pnpm test`; `actions/upload-artifact` do `playwright-report/` em falha; `docker compose ... down -v` no `always` |

### `.github/workflows/deploy.yml`
`on: push: branches: [main]`.

| Job | Passos |
|---|---|
| `ci` | `uses: ./.github/workflows/ci.yml` |
| `publicar` | `needs: ci`; `permissions: {contents: read, packages: write}`; `docker/login-action@v3` em `ghcr.io` com `GITHUB_TOKEN`; `docker/metadata-action@v5` com tags `type=sha,prefix=sha-,format=short` e `latest`; `build-push-action@v6` `push: true` pras duas imagens |
| `deploy` | `needs: publicar`; `environment: production` (required reviewer = aprovação manual); `appleboy/ssh-action@v1` com `DEPLOY_HOST`, `DEPLOY_USER`, `DEPLOY_SSH_KEY`; script: `cd $DEPLOY_PATH/src && git pull --ff-only && export IMAGE_TAG=sha-${GITHUB_SHA::7} && docker compose -f docker-compose.prod.yml pull && docker compose -f docker-compose.prod.yml up -d --remove-orphans && sleep 5 && curl -fsS http://localhost/api/health && docker image prune -f` |

### `.github/dependabot.yml`
`schedule.interval: weekly`; ecosystems `uv` (`/src/backend`), `npm` (`/src/frontend`), `github-actions` (`/`), `docker` (`/src/backend` e `/src/frontend`).

### Configuração manual no GitHub
Secrets: `DEPLOY_HOST`, `DEPLOY_USER`, `DEPLOY_SSH_KEY` (ed25519 dedicada), `DEPLOY_PATH` (clone no servidor, com `src/.env` preenchido). Environment `production` com required reviewer. Branch protection em `main`: job `ci` verde + 1 review. Ativar secret scanning + push protection.

Rollback: no servidor, `cd $DEPLOY_PATH/src && IMAGE_TAG=sha-<anterior> docker compose -f docker-compose.prod.yml up -d`.

Validação local dos workflows: `rtk docker run --rm -v "$PWD:/repo" -w /repo rhysd/actionlint:latest`.

## 8. E2E (`src/e2e/`, etapa BACKEND)

Playwright, **um** cenário feliz contra o compose dev com `LLM_PROVIDER=fake` e `EMAIL_BACKEND=file`, Chromium só.

```
src/e2e/
├── package.json          pnpm; dev dep @playwright/test; scripts: test = playwright test
├── playwright.config.ts  baseURL http://localhost (env E2E_BASE_URL), retries 1, trace on-first-retry, reporter html
├── fixtures/processo.pdf PDF com camada de texto (~2 KB), gerado uma vez com tests/fixtures.py do backend e commitado
└── tests/fluxo-completo.spec.ts
```

Cenário: login `admin`/`admin12345` → upload de `fixtures/processo.pdf` → abre o processo → **Analisar** → checklist exibe `1003966-15.2022.4.01.4301` e matrícula `6.351` → **Agendar** com a sugestão → card mostra as duas datas → **Gerar edital** → markdown contém o nome do juiz → **Enviar pra marketing** → status `enviado` → `/marketing` lista o envio. Asserções por texto visível; seletores por `getByRole`/`getByLabel`.

Rodar local: `cd src && docker compose up -d --build --wait && cd e2e && pnpm install && pnpm exec playwright install chromium && pnpm test` (usuário `admin` criado antes via CLI).

## 9. Logs

nginx propaga `X-Request-ID: $request_id`; backend loga JSON em stdout (spec backend §6). `docker compose logs -f backend | jq` filtra por `request_id`. Sem agregador no v1.
