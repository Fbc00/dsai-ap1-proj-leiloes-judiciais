## 1. Modelo de dados (Postgres)

Todas as tabelas: `id UUID PK default gen_random_uuid()`, `criado_em timestamptz default now()`.

| Tabela | Colunas |
|---|---|

| `tentativas_login` | `chave text` (`"user:<username>"` ou `"ip:<ip>"`), `em timestamptz` |
| `processos` | `nome_arquivo text`, `caminho_pdf text`, `status text` (`recebido\|analisando\|analisado\|erro`), `numero_processo text null`, `vara text null`, `erro text null`, `texto_extraido text null`, `analisado_em timestamptz null` |
| `checklists` | `processo_id FK unique`, `dados jsonb` (schema `Checklist`), `atualizado_em timestamptz` |

| `bloqueios_agenda` | `data date unique`, `motivo text` |
| `leiloes` | `processo_id FK ON DELETE CASCADE`, `primeiro_leilao_em timestamptz`, `segundo_leilao_em timestamptz`, `status text` (`agendado\|cancelado`) |

Migration inicial concede à role `leiloes_app`: `GRANT SELECT, INSERT, UPDATE, DELETE ON ALL TABLES IN SCHEMA public` + `ALTER DEFAULT PRIVILEGES IN SCHEMA public GRANT SELECT, INSERT, UPDATE, DELETE ON TABLES TO leiloes_app`. Nenhum DDL pra `leiloes_app`.

Migration `0007`: revoga `anon`, `authenticated` e `service_role` (roles da Data API do Supabase) de tabelas e sequences do `public`, inclusive nos default privileges (no-op onde essas roles não existem); liga RLS em todas as tabelas do `public` e cria a policy `acesso_app` (`FOR ALL TO leiloes_app USING (true) WITH CHECK (true)`) em cada tabela da app; `alembic_version` fica com RLS e sem policy. Toda tabela nova liga RLS e cria `acesso_app` na mesma migration (`tests/test_migracoes.py` falha se faltar).

## 3. API (`/api`, JSON, erros no formato `ErroOut`)

Toda rota exceto `POST /auth/login` e `GET /health` exige sessão → senão `401 {"detail":"Não autenticado"}`. Usuário com `ativo=false` → sessão inválida (`401`).
Todo `POST/PUT/PATCH/DELETE` exceto `POST /auth/login` exige header `X-CSRF-Token` igual ao cookie `csrf_token` → senão `403 {"detail":"CSRF inválido"}`.
Rotas marcadas **[admin]** exigem `perfil=admin` (`Depends(exige_admin)`) → senão `403 {"detail":"Sem permissão"}`. As demais servem aos dois perfis.

`GET /health` → executa `SELECT 1` no banco → `200 {"status":"ok"}`; banco não responde → `503 {"detail":"Banco indisponível"}` (sem auth; usado pelo deploy e pelo e2e).

**Regras de data** (todas em `TIMEZONE`, hora fixa `HORARIO_LEILAO`, default `10:00`):
- Dia **livre** = dia útil (seg–sex) **e** não feriado (`holidays.country_holidays("BR", subdiv="PA", years=...)`) **e** não está em `bloqueios_agenda`. Não há limite de leilões por dia — outros leilões no mesmo dia não bloqueiam.
- `D` candidato percorre `hoje+30` até `hoje+45` (dias corridos, inclusive), em ordem. `D` e `D+7` precisam ambos ser livres. Primeiro `D` que satisfaz vira sugestão.
- `primeiro_leilao_em = D às HORARIO_LEILAO`; `segundo_leilao_em = primeiro + 7 dias`, mesma hora. Sempre.
- Data manual (`primeiro_leilao_data`) passa pelas mesmas regras, inclusive a janela 30–45; a hora é sempre `HORARIO_LEILAO`.
- Funções puras em `agenda/service.py`: `candidatos(hoje: date) -> list[date]`, `motivo_indisponivel(d: date, bloqueios: dict[date, str], feriados: dict[date, str]) -> str | None`. `sugerir_datas(session, hoje: date)` recebe `hoje` como parâmetro (testável sem congelar relógio); o router passa `date.today()` em `TIMEZONE`.

**DOCX** (`app/editais/docx.py`, `markdown_para_docx(markdown: str) -> bytes` com `python-docx`): conversor simples, linha a linha — `# `→Heading 1, `## `→Heading 2, `**x**`→run em negrito, `1. `/`- `→parágrafo com estilo `List Number`/`List Bullet`, linha em branco separa parágrafos, resto é parágrafo normal. Nada além disso (sem tabelas, links, imagens).

**Template** (`app/editais/templates/edital.md.j2`): cópia de `SPEC/referencias/MINUTA DE EDITAL DE LEILÃO - ESTADUAL.md` (única minuta do v1; `checklist.tipo_justica` só é exibido) com estas substituições:
- Juiz e vara → `checklist.juiz`, `checklist.vara`; nº processo → `checklist.numero_processo`.
- Valor da execução → `checklist.execucao.valor_divida` formatado `R$ 1.234,56` + por extenso (`num2words`, `lang="pt_BR", to="currency"`).
- Exequente/Executado(s) → nome, CPF/CNPJ, advogados com OAB.
- Datas 1º/2º leilão → `dd/mm/aaaa às HH:MMh` em `TIMEZONE`.
- Local → `LEILOEIRO_SITE`, `LEILOEIRO_NOME`, `LEILOEIRO_JUCEPA`, `LEILOEIRO_TELEFONE`.
- Descrição do bem → um bloco por `bem` em `checklist.bens` (descrição, matrícula). Ônus → `hipoteca`/`outras_penhoras` se houver, senão texto padrão da minuta com data de hoje. Localização, fiel depositário → do bem.
- Última avaliação → `valor_reavaliacao` se houver senão `valor_avaliacao`. Lance 1º = última avaliação. Lance 2º = 70% (arredonda `ROUND_HALF_UP` 2 casas). Todos com extenso. Vários bens → soma pra lance.

## 4. LLM

```python
class LLMClient(Protocol):
    async def structured(self, *, system: str, user: str, schema: type[T]) -> T: ...
```

- `get_llm_client(settings) -> LLMClient` escolhe por `LLM_PROVIDER`; valor desconhecido → `ValueError`.
- `fake`: devolve `schema.model_validate(json.load(app/llm/fixtures/<schema.__name__>.json))`. Fixtures baseadas em `SPEC/referencias/DOC 1 modelo checklist - imoveis.md` (processo 1003966-15.2022.4.01.4301; valores de avaliação ausentes no modelo são fictícios). É o default em dev e o **único** permitido em teste.
- `anthropic`: `AsyncAnthropic().messages.parse(model=settings.ANTHROPIC_MODEL, max_tokens=16000, messages=[{"role":"user","content":user}], system=system, output_format=schema)` → `response.parsed_output`.
- `app/processos/prompts.py`: system prompts em português pra checklist e pra relatório, instruindo `null` quando não achar, citar `ref` dos autos e classificar `tipo_justica` pela vara (`"Vara Federal"`/`"Justiça Federal"` → `federal`; vara de comarca estadual → `estadual`; dúvida → `null`). Texto do PDF cortado em `LLM_MAX_CHARS` antes do prompt.
- Toda resposta de `Checklist`/`Relatorio` é apresentada ao usuário com o aviso fixo "Gerado por IA a partir do PDF — revise antes de usar" (responsabilidade do frontend; backend não tem gate de revisão).

## 6. Segurança (mínimo obrigatório)

| Risco | Medida | Onde |
|---|---|---|
| SQL injection | Só SQLAlchemy ORM / `text()` com bind params. Proibido f-string em SQL. Teste envia `' OR 1=1 --` em campos de filtro e confere que nada vaza. | backend |
| CSRF | Double-submit: cookie `csrf_token` (32 bytes `secrets.token_urlsafe`) + header `X-CSRF-Token` em mutações; comparação `hmac.compare_digest`. Cookies `SameSite=Strict`. | backend middleware (frontend manda o header) |
| Sessão | Token 32 bytes aleatório; banco guarda só `sha256(token)`; cookie HttpOnly; expiração `SESSION_TTL_HOURS` (default 12); logout apaga linha. | backend |
| Senha | argon2id (`pwdlib[argon2]`). Nunca logada. Comparação só via verify. | backend |
| Brute force | Tabela `tentativas_login`: falha grava `user:<username>` e `ip:<ip>`. Se qualquer chave tem ≥ `LOGIN_MAX_TENTATIVAS` (default 5) nos últimos `LOGIN_JANELA_MIN` (default 15) → `429` + `Retry-After`. Sucesso limpa chave do usuário. IP vem de `X-Forwarded-For` (primeiro da lista) só se `TRUST_PROXY=true` (nginx sobrescreve com `$remote_addr`; valor enviado pelo cliente nunca chega ao backend). Reforço: nginx `limit_req_zone` 5r/m em `/api/auth/login`. | backend + nginx |
| Enumeração de usuário | Login falho sempre `401 Credenciais inválidas`; verify roda mesmo quando usuário não existe ou está inativo (hash dummy). | backend |
| Autorização | `Depends(usuario_atual)` em tudo; `Depends(exige_admin)` nas rotas **[admin]** → `403 Sem permissão`. Checagem no backend sempre; o frontend só esconde botões. Admin não desativa/rebaixa a si mesmo. Troca de senha e desativação invalidam sessões. | backend |
| Logs | JSON em stdout (`app/logging.py`): `ts`, `level`, `logger`, `msg`, `request_id`, `method`, `path`, `status`, `duration_ms`, `usuario_id`. `request_id` vem do header `X-Request-ID` (setado pelo nginx) ou é gerado. Nunca: corpo de request/response, senha, token, cookie, PDF, texto extraído. `LOG_LEVEL` em env. | backend + nginx |
| Permissão de banco | App conecta como `leiloes_app` (sem CREATE/ALTER/DROP). Migrations rodam como `leiloes_owner`. Grants na migration inicial + `ALTER DEFAULT PRIVILEGES`. RLS em todas as tabelas (migration `0007`, policy `acesso_app` pra `leiloes_app`). URL com host fora de `postgres`/`localhost`/`127.0.0.1` (ex.: Supabase) exige `?ssl=require` (ou `verify-ca`/`verify-full`); `sslmode` em URL asyncpg é recusado no startup. | config, docker/supabase, alembic |
| Envs e segredos | `pydantic-settings`, `SecretStr` pra senhas/chaves. `.env` no `.gitignore`; `.env.example` só com placeholders. Agente de IA não lê `.env`. Nenhum segredo, PDF ou texto extraído em log. | backend, repo |
| Upload | Content-type `application/pdf` **e** magic bytes `%PDF-`; limite `MAX_UPLOAD_MB` (default 50) no backend e `client_max_body_size` no nginx; arquivo salvo como `<uuid>.pdf` em `MEDIA_ROOT` (fora do web root); nome original só no banco. | backend + nginx |
| XSS | Jinja2 gera Markdown; frontend renderiza sem HTML cru. Headers CSP no nginx. | backend + frontend + nginx |
| Erros | `debug=False` em prod; handler genérico devolve `500 {"detail":"Erro interno"}` sem stack trace. | backend |

## 9. Testes

`pytest` + `pytest-asyncio` + `httpx.AsyncClient(transport=ASGITransport(app))`. Postgres real (`DATABASE_URL_TEST`, banco `leiloes_test`, criado pelo `01-roles.sh`). `conftest.py`: cria tabelas via `Base.metadata.create_all` no início da sessão, cada teste roda dentro de transação com savepoint (`join_transaction_mode="create_savepoint"`) e dá rollback. LLM sempre `fake`; e-mail sempre `file`. PDF de fixture gerado com `reportlab` (dev dep) em `tests/fixtures.py` (`make_pdf(texto) -> bytes`, `make_pdf_sem_texto() -> bytes`). Fixture `cliente_logado` já com cookies + header CSRF; `cliente` cru pra testar 401/403.

Rodar: `cd src && docker compose exec backend uv run pytest tests/test_<area>.py`. Só o teste da feature; suíte inteira só no CI ou se pedirem.

Fixture `cliente_logado` é admin; fixture `cliente_operador` pra testar `403 Sem permissão` nas rotas **[admin]**.
